# Make claim eligibility follow Permanent Collectible ownership

New protocol deployments bind the fixed always-allow claim adapter because `RewardLedger` already requires every claimed identity to be permanent and owned by the caller. A configurable per-wallet allowlist inserted an operator into an otherwise self-service collector flow and made a successful Commitment insufficient to claim the reward it activated. Configurable gates remain readable for historical deployment evidence and isolated denial tests, but `DeployProtocol` can no longer select one. The earlier Base Sepolia deployment required replacement because its ledger stored the old gate address immutably. The current staging manifest now records the fixed always-allow adapter with a zero administrator, so that historical replacement requirement is satisfied; production eligibility for regulated assets remains a separate launch decision rather than a routine administrator approval.
