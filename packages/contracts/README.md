# Contracts

This package is the Foundry boundary for ORBIT 4444. `AttributeRegistry` batch-loads the checked collection assignment, validates identity codes and ordering, verifies the manifest commitment, and seals irreversibly before launch. Its tests read the exact canonical manifest generated by `packages/config` and compare every onchain attribute view.

`FuelCore` is the single authority for the hybrid ownership state machine. It exposes the Liquid Token ERC-20 surface, deploys the immutable `FuelMirror` ERC-721 surface, owns Discovery Draw ID selection, and enforces Commitment, launch, pause, freeze, recovery, and venue controls. `FuelMirror` forwards state-aware `tokenURI` reads to a metadata renderer that becomes immutable at launch. Immediate, deterministic, and deferred discovery adapters supply entropy only; they cannot choose or reserve identities.

Production discovery creates one Chainlink VRF request per acquisition of up to 64 whole units. The coordinator callback only stores one verified seed; permissionless finalization derives per-request entropy and applies at most eight retryable FuelCore mutations per transaction. Finalization is FIFO because draw order changes a shared without-replacement pool. Requests expose request time, fulfillment time, progress, and a 15-minute delayed threshold. Fully cancelled queue heads can be skipped without replacement randomness; active delayed requests cannot be cancelled or rerolled.

Ownership tests include the QUOTRONS V1 stale-approval regression and stateful deferred-discovery fuzzing. The invariant profile exercises 2,048 modeled state-machine calls per invariant while checking wallet backing, identity partitioning, permanent-state monotonicity, mirror balances, and the liquid-supply-plus-permanent-count cap.

Solidity is pinned to 0.8.26 in `foundry.toml`. Add external libraries only at reviewed, immutable revisions.

## Canonical Market

`CanonicalMarketRegistry` records and irreversibly seals one dynamic-fee `$FUEL`/WETH Uniswap v4 pool, its correctly permissioned `CanonicalFeeHook`, and its dedicated `CanonicalRouter`. `CanonicalHookDeployer` exposes the CREATE2 init-code hash and predicted address used to mine a salt whose low address bits exactly match the hook callbacks, then rejects deployment with any other salt. The router exposes exact-input and exact-output quotes and swaps, applies deadlines and minimum/maximum bounds, and wraps or unwraps native ETH only at the edge. The hook overrides the ordinary LP fee to zero and custom-accounts 3% against the gross WETH leg: 2% to the reward pot, 0.85% to the Protocol-Owned Liquidity pot, and 0.15% to the creator pot. Integer remainders are assigned to the creator pot so the three destinations always sum to the full 3% charge.

`FuelCore` cannot launch until a sealed Canonical Market is configured. It permits the registered PoolManager to settle `$FUEL` only while that hook has an active swap from the sealed router, and the hook checks the original trader even when output is sent to another recipient. A different pool on the same PoolManager cannot settle `$FUEL`. Known alternate venue runtime code hashes can be blocked during setup and become immutable at launch; ordinary wallet transfers remain available. Because ordinary transfers remain available, a novel transfer-mediated venue with an unconfigured code hash cannot be categorically excluded. That limitation is part of the Canonical Market guarantee, not an undisclosed assumption.

## Genesis Liquidity

`GenesisLiquidityVault` initializes the sealed Canonical Market at tick `±51,600`, translating the sign from the actual Liquid Token/WETH address order so the opening marginal price remains approximately `0.005743 WETH` per Liquid Token. With WETH as currency0 it uses `[-887220, 51600]`; with the Liquid Token as currency0 it mirrors the position to `[-51600, 887220]`. The vault derives liquidity from the complete `4,444e18` supply, settles only the Liquid Token delta, and records the at-most-two wei left by conservative v4 liquidity rounding as explicit `roundingDust`.

The vault has one operator-only, deadline-bounded initialization call and an add-only PoolManager callback. After that call it exposes only read and validation functions: there is no liquidity-removal, fee-withdrawal, token-rescue, fallback, or arbitrary-call interface. The vault and PoolManager must both be Discovery Draw-exempt before funding. `FuelCore.launch()` then freezes those exemptions with the rest of the launch configuration.

The Base Sepolia seeding script requires the deployer to own the complete liquid supply and to remain the `FuelCore` owner. It deploys the vault, configures both exemptions, approves the vault, then atomically pulls the full supply and initializes/seeds the pool in one transaction. A hostile permissionless pool initialization therefore fails before any Liquid Token leaves the deployer. After seeding, the script clears the deployer's setup exemption and verifies all immediate postconditions:

```bash
export CANONICAL_MARKET_REGISTRY_ADDRESS=0x...
export TREASURY_ADDRESS=0x... # optional; checked for zero retained Liquid Tokens
forge script script/DeployGenesisLiquidity.s.sol:DeployGenesisLiquidity \
  --rpc-url "$BASE_SEPOLIA_RPC_URL" \
  --broadcast
```

After the transaction is confirmed and before the first market swap, run the read-only verifier against a fresh RPC snapshot:

```bash
export DEPLOYER_ADDRESS=0x...
export GENESIS_LIQUIDITY_VAULT_ADDRESS=0x...
forge script script/VerifyGenesisLiquidity.s.sol:VerifyGenesisLiquidity \
  --rpc-url "$BASE_SEPOLIA_RPC_URL"
```

The verifier intentionally requires the untouched opening price and immediate post-seed Liquid Token balances. It does not compare raw WETH balances on either the singleton PoolManager or vault because unrelated pools and unsolicited donations can change them; the add-liquidity callback itself requires a zero WETH position delta. Canonical swaps remain locked until `FuelCore.launch()`, including swaps whose recipient is an exempt protocol account. The verifier is a launch precondition, not a health check to run after trading begins. The later composition launch records the confirmed vault address and executes the one-way launch freeze.

## Protocol-Owned Liquidity

`ProtocolLiquidityVault` is deployed before Canonical Market registration so its address can be sealed into `CanonicalFeeHook` as the only liquidity-pot destination. After the registry is sealed, the owner binds that exact registered hook and irreversibly seals the cross-contract configuration. The owner may later pause new cycles or replace the executor, but neither role can replace the hook, Settlement Asset, Liquid Token, PoolManager, market, or liquidity destination.

Each executor cycle supplies aligned lower/upper ticks, a positive liquidity amount, a maximum WETH spend, and a deadline. The vault pulls at most the unfilled portion of that maximum from the hook's liquidity pot, combines it with previously queued WETH, and adds a uniquely salted real Uniswap v4 position. Its PoolManager callback rejects every nonzero Liquid Token delta and requires an exact positive WETH delta bounded by both the executor maximum and the destination-locked queue. Actual token balance changes and position liquidity are measured before the cycle is recorded.

Unused WETH remains either in the hook's liquidity pot or in the vault's explicit `queuedWeth` accounting for a later cycle. Consumed WETH accumulates in `permanentlyLockedWeth`; each completed position remains owned by the vault. There is no position-removal, fee-collection, WETH-withdrawal, Liquid-Token-withdrawal, rescue, fallback, or arbitrary-call interface.

Focused verification:

```bash
forge test test/ProtocolLiquidityVault.t.sol
forge test test/ProtocolLiquidityVaultIntegration.t.sol
```

## Reward Epochs and sealed conversion

`EpochConverter` is the only destination allowed to pull the Canonical Fee Hook reward pot. An appointed Keeper can open at most one Reward Epoch every 60 seconds once at least `0.04 WETH` is available. Each opening clips at `40 WETH`, leaves any excess in the hook, and adds equal quarters to four independent Reward Track queues; the final track receives the deterministic integer remainder. One track execution clips at `10 WETH`, so unprocessed WETH remains a Deferred Track Budget assigned to that track rather than being redistributed.

Before operation, the owner binds the Canonical Fee Hook and all four stock-token/adapter pairs, the `RewardLedger` seals the converter, and `EpochConverter.sealConfiguration()` verifies every relationship and makes it immutable. The owner can subsequently pause execution or replace the Keeper but cannot redirect WETH, USDC, MockStock, pool, adapter, or Reward Ledger destinations. Failed routes revert independently without changing their WETH queue, so healthy tracks and later epochs remain available.

`SepoliaV4ConversionAdapter` stores and re-verifies the configured WETH/USDC and USDC/MockStock v4 pool IDs, then performs the exact-input two-hop route through the project-seeded venue. MockStock goes directly to `RewardLedger`. Both the adapter and converter measure the ledger balance increase instead of trusting venue or adapter return values. `DeterministicConversionAdapter` exposes the same interface with a one-to-one valueless test conversion for isolated success and failure tests.

Focused verification:

```bash
forge test test/EpochConverter.t.sol
forge test test/EpochConverterRewardLedger.t.sol
```

## Complete deployment and launch

Run the repository-level wrapper rather than invoking `DeployProtocol.s.sol` directly. The wrapper selects only Anvil (`31337`) or Base Sepolia (`84532`), broadcasts from an unlocked Anvil account or the untracked Base Sepolia key, waits for every receipt, identifies the one-way `FuelCore.launch()` receipt, and finalizes the chain manifest with all transaction hashes and the launch block. A completed rerun performs read-only bytecode, owner/role, pool-key, route, destination, balance, manifest-hash, metadata, exemption, protection, and seal checks; it does not duplicate a transaction.

```bash
anvil
RPC_URL=http://127.0.0.1:8545 pnpm deploy:protocol
RPC_URL=http://127.0.0.1:8545 pnpm deploy:protocol # read-only idempotence check
```

For Base Sepolia, set `DEPLOYMENT_ENVIRONMENT=staging`, `RPC_URL`, `DEPLOYER_PRIVATE_KEY`, `SELF_FUNDED_TEST_ASSETS=true`, `GUARDIAN_ADDRESS`, `KEEPER_ADDRESS`, `LIQUIDITY_EXECUTOR_ADDRESS`, and `CREATOR_ADDRESS` in an untracked environment. The environment selector must agree with the connected chain and chooses the checked manifest; contract addresses never come from the environment. The operational roles may deliberately share the deployer in this valueless POC. Recovery must remain independent: either provide an existing `RECOVERY_AUTHORITY_ADDRESS` whose code reports a threshold of at least two, or provide a distinct `RECOVERY_COSIGNER_ADDRESS` so the deployment creates the Base-Sepolia-only 2-of-2 `TestnetThresholdRecoveryAuthority`. The local-only `DevelopmentRecoveryAuthority` cannot be deployed on a public chain.

The self-funded profile reads the schema-v1 venue manifest, independently verifies its asset labels, operators, supplies, official `PoolManager` binding, five pool keys, seed prices, and active liquidity before creating any protocol contract, and then reuses those addresses. The Canonical Market uses the same WETH-like asset consumed by the sealed conversion routes. `pnpm test:deployment:base-fork` proves this full path against a disposable fork without spending live ETH.

The deployment writes schema version 2 manifests. They contain all code addresses, role accounts, the selected product-identity key, identity manifest hash, immutable metadata locations, five conversion pool keys, the Canonical Market key, seal proofs, the launch block, and confirmed transaction hashes. Reruns require a contiguous, deployer-attributable transaction sequence anchored to every top-level contract creation and ending with the exact `FuelCore.launch()` call. Mutating an expected role, pool key, identity input, code address, transaction history, or seal makes the rerun fail before it can take any deployment action. The complete empty-chain and mutation test is `pnpm test:deployment`.

## Valueless conversion venue fixtures

`MockStock` provides fixed-supply AAPLc, GOOGLc, METAc, and NVDAc stand-ins whose names and symbols must contain `MOCK` or `TEST`. Its operator can pause transfers or reject one recipient solely to reproduce issuer-controlled route failures. `MockWETH` and six-decimal `MockUSDC` are local deterministic fixtures. `MintableTestToken` supplies visibly labelled, operator-mintable WETH-like and USDC-like assets for the faucet-independent Base Sepolia profile.

`TestConversionVenue` initializes real Uniswap v4 pools through the official `PoolManager` interface. It derives currency ordering from addresses, uses a dedicated test-only `4,444` fee / `11` tick-spacing key instead of the already initialized public `3,000` / `60` WETH/USDC key, seeds full-range liquidity at explicitly artificial ticks, quotes exact input without mutating pool state, executes minimum-output swaps, and exposes only configurations that passed price and active-liquidity verification. The artificial targets are approximately 100 test USDC per WETH and 1 test USDC per MockStock. They deliberately do not imitate equity prices.

Uniswap v4 core is pinned as a git submodule to tag `v4.0.0`, commit `e50237c43811bd9b526eff40f26772152a42daba`.

## Base Sepolia test venue deployment

Set `BASE_SEPOLIA_RPC_URL` and `DEPLOYER_PRIVATE_KEY` in an untracked `.env`. Two profiles use the same script:

- `SELF_FUNDED_TEST_ASSETS=true` is the accepted POC profile. It deploys clearly labelled mintable WETH-like and USDC-like test assets, requires only Base Sepolia ETH for gas, and still uses the official Uniswap v4 PoolManager.
- `SELF_FUNDED_TEST_ASSETS=false` retains the original faucet-issued WETH/Circle test USDC path for historical reproducibility but is not the selected deployment profile.

Then run:

```bash
set -a
source ../../.env
set +a
forge script script/DeployBaseSepoliaTestVenue.s.sol:DeployBaseSepoliaTestVenue \
  --rpc-url "$BASE_SEPOLIA_RPC_URL" \
  --broadcast
```

Both profiles refuse any chain other than Base Sepolia and any non-official Uniswap v4 PoolManager. The official profile additionally hard-rejects non-official WETH or Circle test USDC. The script deploys four visibly labelled mock stocks, initializes one WETH/USDC and four USDC/MockStock pools, performs executable round trips in both directions, and re-verifies ordering, pool IDs, seed prices, and active liquidity. It deliberately never writes `deployments/84532.json`, including during a dry run.

After the broadcast command returns with confirmed receipts, record the printed public addresses in `deployments/84532.venue.json`. This checked, schema-validated staging configuration is deliberately separate from credentials and from the final protocol manifest. Then run the read-only verification pass against a fresh RPC snapshot:

```bash
forge script script/VerifyBaseSepoliaTestVenue.s.sol:VerifyBaseSepoliaTestVenue \
  --rpc-url "$BASE_SEPOLIA_RPC_URL"
```

`TEST_VENUE_CONFIGURATION_PATH` may point the verifier at a different public candidate file, and `DEPLOYMENT_MANIFEST_PATH` may redirect its verified output. Neither setting contains an address. Only this second pass can write the canonical manifest. It validates the deployed bytecode-bearing addresses, operators, stock metadata and supply, official infrastructure bindings, all five pool keys, exact artificial seed prices and liquidity values, repeated exact-input quotes in both directions, and the 10 WETH maximum clip from confirmed onchain state.
